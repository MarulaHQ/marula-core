# Tech stack

What the repo is built with, as of the Wave 41 rebrand. Versions come from the
manifests, so this file goes stale only when a manifest moves. Nothing here is a
recommendation. Three choices look arbitrary enough to be worth a note in place, and
those notes sit in §1, §12, and §13.

Two license families run through the tree. The core is AGPL-3.0-or-later. The public
SDK under `packages/sdk` and every connector under `plugins/` are Apache-2.0, so they
can ship separately from the server.

## 1. Monorepo shape

| Boundary | Definition | What it owns |
| --- | --- | --- |
| Cargo workspace | `Cargo.toml`, resolver 2, edition 2021 | `desktop/` + `crates/*` + `plugins/connectors/*` |
| pnpm workspace | `pnpm-workspace.yaml` | `apps/*`, `packages/*`, `native`, `website` |
| Task graph | `turbo.json` | `dev`, `build`, `lint`, `typecheck`, `test` |

Rust is pinned to `stable` with `rustfmt` and `clippy` (`rust-toolchain.toml`).

The `[profile.desktop]`, `[profile.dev]`, and `[profile.test]` blocks in the root
`Cargo.toml` are not tuning for speed. They cap debuginfo so parallel lanes can share
one build cache at `.kilo/target-shared` without filling the disk.

## 8. Live delivery and background work

Live delivery is one leg: the SSE stream at `GET /api/events/stream`, served by
`crates/core-api`. `crates/core-api/src/realtime.rs` listens to the Postgres
`marula_events` NOTIFY channel and fans contract-event frames out to org-scoped
subscribers; presence is in-process memory with a TTL, relayed between replicas on
the `marula_presence` NOTIFY channel and emitted as `type: "presence"` frames on
the same stream. `crates/core-api/src/routes/events.rs` serves the stream, and
`routes/presence.rs` serves the roster read and the heartbeat write. There is no
separate socket service. `crates/worker` owns the queue runner plus these loops: SLA, PM,
rotation, dedupe, time, digest, CSAT, automations, notifications, email, delivery,
search indexer, outbound webhooks, project billing, decision fan-out, the two
retention sweeps (workflow runs, event outbox), and org usage refresh. The event
stream it publishes to is capped at a fixed entry count — see
[worker-cadence](worker-cadence.md) for why the cap is a count, not an age.

## 11. AI providers

`crates/core-api/src/ai.rs` resolves a provider per organization from sealed BYOK
config.

| Provider | Embeddings | Transcription |
| --- | --- | --- |
| OpenAI | yes | yes (`gpt-4o-transcribe`) |
| Ollama | yes (local) | yes (`whisper`) |
| Anthropic | no embeddings API | no |
| Custom | no base-URL setting yet | no |

Unconfigured, unsupported, or undecryptable keys all degrade to the `None` provider
rather than erroring, so the vector leg is optional everywhere.

## 12. Connectors and plugins

`plugins/connectors/` holds Apache-2.0 HTTP adapters. They talk to the public API only
and never import the core, which is what keeps the license split honest.

| Crate | Target |
| --- | --- |
| `adapters-core` | Shared vendor auth, native pagination, org-to-client mapping |
| `qbo-export-sync` | QuickBooks Online |
| `xero-export-sync` | Xero |
| `dms-sync` | Document management systems, including Hudu |
| `ci-feeders` | Configuration-item feeders, including NinjaOne |
| `m365-graph` | Microsoft 365 |
| `app-bridges` | Hosted app bridges, HMAC-signed |
| `unifi` | UniFi inventory |
| `threecx` | 3CX call control |
| `mapbox` | Mapbox routing, behind the `core-routing` seam |

`plugins/wasm/` holds three `wasm32-unknown-unknown` `cdylib` plugins:
`escalation-widget`, `asset-tag-validator`, `triage-note-action`. They are detached from
the Cargo workspace on purpose, so plugin artifacts never enter the shared build cache.
The Extism runtime is not wired yet; `plugin-host` exposes a `PluginRuntime` interface
for it. Signing and rotation are in
`docs/reference/plugin-signing-rotation-runbook.md`.

The routing provider architecture behind `core-routing` is written up in
`docs/adr/0014-routing-provider-architecture.md`.

## 13. Observability

`crates/core-otel` wraps OpenTelemetry 0.32 (traces, metrics, logs) on `tracing` 0.1 and
`tracing-subscriber` 0.3 with an env filter, bridging through `tracing-opentelemetry`
0.33 and `opentelemetry-otlp` 0.32. It adds named instruments, a redaction pass for
secret-like values and high-cardinality segments, and an opt-in filter for sqlx spans.

The `opentelemetry-otlp` build uses the blocking reqwest client, not the async one. The
SDK's batch processors call `block_on` on their own threads, where the async client
panics with "no reactor running" (open-telemetry-rust #2673, #3125).

| Component | Image |
| --- | --- |
| Collector | `otel/opentelemetry-collector-contrib` 0.118.0 |
| Traces | Tempo 2.7 |
| Logs | Loki 3.6 |
| Dashboards | Grafana 11, provisioned |
| Errors | GlitchTip 6.2.6 |
| Uptime | Uptime Kuma 2.5.5 |

Configs live in `deploy/observability/`.

## 14. Desktop app — `desktop/`

Tauri 2 (`tray-icon`, `image-png`) plus `tauri-plugin-updater` and
`tauri-plugin-single-instance`, over `postgresql_embedded` 0.20. The binary starts an
embedded Postgres, boots `core-api`, and serves the web app in one double-clickable
window. It manages multiple windows, handles `marula://` deep links, sends ZPL to label
printers, and persists window state. Build and packaging are in
`docs/desktop-release.md`.

## 16. Testing

| Layer | Tooling |
| --- | --- |
| Rust unit and integration | `cargo test` per crate; ~80 test files in `core-api`, 32 in `core-db` |
| Rust against real Postgres | `testcontainers` 0.23 + `testcontainers-modules` 0.11, reusable containers |
| Rust properties and ordering | `proptest`, `serial_test` 3 |
| Golden files | OpenAPI pins, event conformance |
| JS and TS | Vitest 3, Testing Library, jsdom |
| Accessibility | `@axe-core/playwright`, baseline at `e2e/axe-baseline.json` |
| Browser E2E | Playwright 1.63, driven by `scripts/e2e-stack.sh` |
| Mobile E2E | Maestro, flows in `native/e2e/flows` |
| Performance | `crates/perf-harness` + `scripts/perf-smoke.sh`; budgets in `docs/perf.md` |
| Mocks | `MockApi` in `apps/web/tests`, `FakeApi` and `FakeSocketFactory` in `native/tests` |

`scripts/e2e-stack.sh` is the only supported way to boot the stack: it creates a
per-run database, picks random high ports, names containers by run id, and writes
`e2e/.e2e-stack.env` for Playwright and the web build to read. `scripts/dev-status.sh`
lists registered runs. The GitHub workflow files in `.github/workflows/` are all
`.disabled`; the checks run through `scripts/`.
