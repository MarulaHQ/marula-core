# How to work a ticket

> **Audience:** both — this is the daily loop for MSP staff; admins run it
> too and see it from the settings side.

## Prerequisites

- A signed-in session on a deployed stack. If you are new, the tutorial
  [your first ticket](../tutorials/first-ticket.md) walks the loop on the
  seeded demo org (`owner@demo.local` / `demo-password-123`).
- Assigned or unassigned, anything on the boards you are a member of.
- If AI assistance is granted to your role, the Agent panel appears on
  ticket detail, and if not, the same loop works without it.

## 1. Pick the work

`/today` is the shared work queue: overdue / due-today / approvals
widgets, open-ticket count, rows with P1–P4 priority chips, assignee
initials, board column, escalation chips. `/tickets` is the full list
with status tabs (Open / In progress / Waiting / Closed / All) — filter
there when the queue needs narrowing.

## 2. Arrive in the workbench

Open a ticket: three panes. Left **Ticket Context** (client, board,
status, SLA ring — and contextual documentation links to relevant KB
articles). Center **Activity** with the composer (note selector,
Attach, AI Assist if granted, Template, Dictate). Right **Agent** panel
(relevant knowledge sources, recommended next step, chat with the agent).

Header actions when you need them: **Close**, **Escalate**, **Link**, the
status/SLA ring, and the **Classic toggle** toward the legacy 3-pane
workspace kept during the workbench-v2 transition — pods (Tickets /
Detail / Timeline with visibility filters, Pod visibility, Arrange pods)
for anyone who wants the old desk back mid-lesson.

The same ticket has Tabs: **Activity / Details / Related / Time Entries /
Files / Notes**.

## 3. Note it (and keep internal things internal)

Compose in Activity. Flip the **Internal note** selector before sending
anything client-internally, attached files through Files, KB context from
the Agent panel's knowledge sources. Approval-gated work: route notes via
the composer rather than external channels — the Activity feed is the
shared record.

## 4. Track the timer, let it become the time entry

The work bar tracks the active timer ("no active timer — the work bar
tracks it" is the hint on `/today`). Start from the ticket, work with the
bar, stop the timer — the entry lands on the ticket's time entries and in
your day's time ledger, without hunting a separate time screen.

## 5. Get it approved and on an invoice

Approvals (/approvals) is where submitted time waits. Approved entries
are what billing consumes, and invoiced entries lock permanently. Your loop
ends where billing begins, and the one-on-one invoice walkthrough is the
[first invoice tutorial](../tutorials/first-invoice.md).

## What you learned

- One screen per ticket. Context left, activity center, agent right.
  Status and SLA live in the header.
- The note→timer→time-entry loop is the product center, not a side quest.
- Approve → bill is a single arrow, and invoiced time locks.
